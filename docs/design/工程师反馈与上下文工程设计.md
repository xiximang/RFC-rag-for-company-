## 1. 背景与目标

### 1.1 当前系统的问题

现有 RAG 系统的回答链路为：

```
用户提问 → 向量检索 + BM25 → RRF融合 → 权限过滤 → Rerank(5→3) → LLM生成 → 返回答案+Sources
```

经过对现有系统（`SearchConsole.tsx`、`chat.py`、`retrieval_service.py`、`generation_service.py`）的分析，存在以下空白：

| 问题 | 现状 | 影响 |
|------|------|------|
| **反馈层级浅** | 只有二元的 Thumbs Up/Down（rating=1/-1），只评价最终答案 | 无法区分是"检索不好"还是"LLM 生成不好" |
| **无中间候选可见** | Rerank 后的 Top-3 结果直接被 LLM 消费，工程师看不见也选不了 | 丢失了最有价值的**检索质量判断信号** |
| **无查询缓存** | Redis 只缓存权限数据（ACL、安全等级），同样的 query 每次走完整流水线 | 高频查询重复 rerank + LLM，成本高、响应慢 |
| **上下文简单截断** | History 最多保留 10 轮，超出直接丢弃，无摘要/无分层 | 长对话早期信息永久丢失，模型"遗忘" |
| **无跨会话记忆** | 每次对话从零开始，不记忆工程师偏好的答案风格或高频查询模式 | 重复劳动，无法积累领域经验 |

### 1.2 核心目标

1. **让工程师参与检索质量判断**：展示 Rerank 后的多个候选，让工程师选择/排序，反馈回流到检索系统
2. **减少重复计算**：缓存高频查询的（query → best_chunks → answer）三元组，相似查询跳过 rerank + LLM
3. **上下文结构化管理**：参考 Pico 的分层思想，把 prompt 拆成稳定段 + 动态段，带 freshness 和预算控制
4. **设计可解释的记忆层**：工程师的每次反馈都有迹可循，不会因文件更新而过期复用

## 2. 设计原则

参考 `context_engineering/` 系列的设计哲学，提炼为本方案的原则：

### 原则 1：稳定段与变化段分离

> 参考: `04-提示词形态与缓存复用设计.md`

Prompt 里的内容不是同一种东西。系统规则、工具说明、查询缓存是稳定的；历史记录、当前请求是动态的。两者分开管理，cache 才有意义。

### 原则 2：记忆要带 freshness

> 参考: `05-结构化的会话记忆.md`

工程师的反馈缓存在知识库更新后可能过期。每条记忆必须带内容哈希（freshness），文档变了就自动失效。

### 原则 3：分层瘦身，不粗暴截断

> 参考: `06-上下文瘦身与输出管理设计.md`

超预算时按优先级裁减：先裁相关记忆 → 再裁历史 → 再裁系统记忆 → 最后才动前缀。当前用户请求永远不裁。

### 原则 4：每一层都该可解释

> 参考: `05-结构化的会话记忆.md` 的召回逻辑

缓存是否命中、记忆为什么被召回、反馈如何影响排序——这些链路都应该是白盒的。

### 原则 5：反馈是数据，不是装饰

工程师的每一次选择/排序/评分，都是高质量的标注数据。它可以用来：
- 训练自定义 Reranker
- 调整 RRF 融合权重
- 作为将来 LLM fine-tuning 的偏好数据

## 4. 第一层：Rerank 候选展示与工程师交互

### 4.1 当前流程的问题

现有 `_retrieve_and_generate()` 的流程中，rerank 后的 chunks 直接被 `generation_service` 消费，没有对外暴露候选列表。

```python
# 当前: chunks 直接传给生成，工程师看不到中间结果
chunks = await retrieval_service.search(...)
result = await generation_service.generate_answer(
    context_chunks=chunks,  # ← 只有 Top-5，无候选信息
    ...
)
```

### 4.2 改动方案

#### 4.2.1 API 改造：ChatResponse 增加 candidates 字段


### 4.3 交互形式设计

| 交互方式 | 前端实现 | 数据价值 |
|---------|---------|---------|
| **排序（Drag & Drop / 点击上下箭头）** | 工程师调整候选顺序 | 完整的 pairwise preference 数据 |
| **评分（1-5星）** | 每个候选下方显示星级 | 绝对质量标注，可计算 nDCG |
| **选择最优** | 点击候选上的「最优」标记 | 二选 preference，最简单 |
| **「确认」按钮** | 工程师确认当前答案已正确 | 强化缓存置信度，`confirmed_count++` |
| **「重新检索」按钮** | 强制走 MISS 路径，忽略缓存 | 处理缓存过期/知识库更新场景 |
| **「手动编辑」** | 允许工程师直接修改答案文本 | 为将来 fine-tuning 提供人工修正数据 |

### 5.3 Freshness 机制

每条 `query_experience` 记录关联了文档级别的 `freshness`。当文档被重新索引时，文档的内容哈希会变化，对应的记忆条目自动失效。

```python
def is_entry_fresh(entry: dict, doc_service) -> bool:
    """检查一条经验记忆是否仍然新鲜（文档未变化）"""
    for doc_id, expected_hash in entry["freshness"].items():
        current_hash = doc_service.get_doc_content_hash(doc_id)
        if current_hash != expected_hash:
            return False
    return True

def refresh_memory(memory: dict, doc_service) -> dict:
    """遍历经验记忆，移除过期条目"""
    fresh_entries = [
        entry for entry in memory["query_experience"]
        if is_entry_fresh(entry, doc_service)
    ]
    memory["query_experience"] = fresh_entries
    return memory
```

### 5.4 记忆渲染到 Prompt

参考 Pico 的 `render_memory_text()`，记忆不是全量塞进 prompt 的，而是按预算渲染：

```python
def render_engineer_memory(
    memory: dict,
    current_query: str,
    max_chars: int = 800,
) -> str:
    """将工程师经验记忆渲染为 prompt 片段"""
    parts = []

    # 1. 高频查询模式摘要（限 200 chars）
    if memory["query_experience"]:
        top_entries = sorted(
            memory["query_experience"],
            key=lambda e: e["confirmed_count"],
            reverse=True,
        )[:3]
        patterns = "；".join(
            f"「{e['query']}」→ {e.get('best_answer_preview', '')[:60]}"
            for e in top_entries
        )
        if patterns:
            parts.append(f"[工程师经验] 高频查询: {patterns}")

    # 2. 当前查询关联的记忆（限 300 chars）
    relevant = find_relevant_experience(
        memory["query_experience"],
        current_query,
        top_k=1,
    )
    if relevant:
        entry = relevant[0]
        parts.append(
            f"[相关经验] 相似查询「{entry['query']}」曾被确认 {entry['confirmed_count']} 次，"
            f"最佳回答: {entry.get('best_answer_preview', '')[:120]}"
        )

    # 3. 任务上下文摘要（限 100 chars）
    if memory["task_context"].get("current_project"):
        parts.append(
            f"[当前任务] 项目: {memory['task_context']['current_project']}"
        )

    text = "\n".join(parts)
    if len(text) > max_chars:
        text = text[:max_chars] + "…"
    return text
```

## 6. 第三层：缓存命中与相似查询匹配

### 6.1 三层匹配策略

> 参考: `04-提示词形态与缓存复用设计.md` 的 prefix hash 思想——先从确定性匹配开始，再到近似匹配。

```python
class QueryCacheMatcher:
    """
    查询缓存匹配器：三层递进匹配。

    第一关：精确哈希（O(1)，无漏报）——完全相同的问题
    第二关：语义向量（近似检索）——意思相同但表述不同
    第三关：关键词 Jaccard（降级匹配）——含关键概念的问题
    """

    SEMANTIC_THRESHOLD = 0.92   # 语义相似度阈值
    KEYWORD_THRESHOLD = 0.60    # 关键词 Jaccard 阈值

    async def find_match(
        self,
        query: str,
        query_embedding: List[float],
        cache_store: "CacheStore",
        top_k: int = 3,
    ) -> Optional[CacheHitResult]:
        """找缓存中最佳匹配，返回最相似的结果"""

        # ── 第一关：精确哈希 ──
        query_hash = self._compute_hash(query)
        exact_match = await cache_store.get_by_hash(query_hash)
        if exact_match and self._is_fresh(exact_match):
            return CacheHitResult(
                match=exact_match,
                match_type="exact_hash",
                similarity=1.0,
            )

        # ── 第二关：语义向量 ──
        semantic_matches = await cache_store.search_by_embedding(
            query_embedding, top_k=5
        )
        for match in semantic_matches:
            if (match.similarity >= self.SEMANTIC_THRESHOLD
                    and self._is_fresh(match)):
                return CacheHitResult(
                    match=match,
                    match_type="semantic",
                    similarity=match.similarity,
                )

        # ── 第三关：关键词 Jaccard ──
        query_tokens = self._tokenize(query)
        keyword_matches = await cache_store.list_recent(limit=50)
        for match in keyword_matches:
            if not self._is_fresh(match):
                continue
            entry_tokens = match.get("query_keywords", []) or self._tokenize(match["query"])
            jaccard = self._jaccard(query_tokens, entry_tokens)
            if jaccard >= self.KEYWORD_THRESHOLD:
                return CacheHitResult(
                    match=match,
                    match_type="keyword_jaccard",
                    similarity=jaccard,
                )

        return None

    def _compute_hash(self, query: str) -> str:
        return hashlib.sha256(query.encode("utf-8")).hexdigest()

    def _tokenize(self, text: str) -> Set[str]:
        """提取文本的关键 token（中英文分词/切分）"""
        # 英文按空格切分 + 中文按字符或 jieba
        # 过滤停用词
        ...

    def _jaccard(self, a: Set[str], b: Set[str]) -> float:
        if not a or not b:
            return 0.0
        return len(a & b) / len(a | b)

    def _is_fresh(self, entry: dict) -> bool:
        """检查缓存条目的 freshness（文档是否变更）"""
        return is_entry_fresh(entry, self.doc_service)
```

### 6.2 缓存命中后的处理

```python
@dataclass
class CacheHitResult:
    match: dict
    match_type: str               # "exact_hash" | "semantic" | "keyword_jaccard"
    similarity: float

class CacheAwareChatService:
    """带缓存感知的聊天服务"""

    async def handle_query(
        self,
        user_id: UUID,
        query: str,
        kb_ids: List[UUID],
        ...
    ) -> ChatResponse:
        query_embedding = await embedding_client.embed(query)

        # 1. 查询缓存匹配
        cache_hit = await self.cache_matcher.find_match(
            query, query_embedding, self.cache_store
        )

        if cache_hit and not self._should_force_refresh(query, user_id):
            # 缓存命中 → 跳过 rerank + LLM
            logger.info(
                "Cache HIT: type=%s similarity=%.2f query=%r",
                cache_hit.match_type, cache_hit.similarity, query,
            )

            # 记录缓存命中
            self._record_cache_hit(cache_hit, user_id)

            return await self._build_response_from_cache(
                cache_hit, conversation_id=...
            )

        # 2. 缓存未命中 → 走完整流水线
        logger.info("Cache MISS: query=%r", query)

        chunks = await retrieval_service.search(...)
        reranked = await rerank_client.rerank(query, chunks, top_k=5)

        # 3. 如果匹配度很高的缓存接近命中但未达到阈值，
        #    把缓存结果作为候选之一提供给工程师
        near_miss = self._find_near_miss(query_embedding, threshold=0.80)
        candidates = self._build_candidates(reranked, near_miss)

        # 4. 返回带候选的 response
        return ChatResponse(
            answer=generated_answer,
            sources=...,
            candidates=candidates,     # 新增：工程师可交互的候选
        )

    def _find_near_miss(
        self, query_embedding: List[float], threshold: float
    ) -> Optional[dict]:
        """
        找接近缓存命中的条目（相似度在 threshold 和 SEMANTIC_THRESHOLD 之间）。
        这些结果作为"候选"呈现给工程师，但不直接作为答案。
        """
        matches = self.cache_store.search_by_embedding(
            query_embedding, top_k=1
        )
        for m in matches:
            if threshold <= m.similarity < self.SEMANTIC_THRESHOLD:
                return m
        return None
```

### 6.3 缓存写入策略

```python
class CacheWritePolicy:
    """控制何时将反馈写入缓存"""

    def should_write_cache(self, feedback: CandidateFeedback) -> bool:
        """
        满足以下条件之一时写入缓存：
        1. 工程师明确点了「确认」按钮
        2. 连续 >= 2 次相同查询被评分为有用（rating >= 4）
        3. 相同查询被确认过的次数 > 3（强化缓存）
        """
        if feedback.action == "approve":
            return True
        if feedback.ratings and all(r >= 4 for r in feedback.ratings.values()):
            # 检查历史，如果是重复确认
            confirm_count = self._get_confirm_count(feedback.query)
            return confirm_count >= 2
        return False

    def should_evict(self, entry: dict) -> bool:
        """满足以下条件之一时淘汰缓存：
        1. Freshness 检查不通过（文档已更新）
        2. 超过 30 天没有被命中
        3. 被工程师标记为「不准确」>= 3 次
        4. 缓存条目超过上限（默认 1000 条），淘汰 LRU
        """
        if not is_entry_fresh(entry): return True
        if self._days_since_last_hit(entry) > 30: return True
        if entry.get("disagreed_count", 0) >= 3: return True
        return False
```

```python
# backend/app/services/context_manager.py

from dataclasses import dataclass, field
from typing import Optional, List, Dict

@dataclass
class SectionBudget:
    """每个 section 的预算控制"""
    max_chars: int           # 该段最大字符数
    floor_chars: int         # 最低保留字符数（不可再低于此值）
    reduction_priority: int  # 裁减优先级（0=最后裁，越大越先裁）
    current_chars: int = 0

DEFAULT_BUDGETS = {
    "prefix":          SectionBudget(max_chars=2000,  floor_chars=800,   reduction_priority=3),
    "engineer_memory": SectionBudget(max_chars=800,   floor_chars=200,   reduction_priority=1),
    "relevant_cache":  SectionBudget(max_chars=600,   floor_chars=100,   reduction_priority=0),
    "history":         SectionBudget(max_chars=3000,  floor_chars=1000,  reduction_priority=2),
    "current_request": SectionBudget(max_chars=8000,  floor_chars=8000,  reduction_priority=99),  # 永不裁
}


class ContextManager:
    """Prompt 上下文管理器：分层组装 + 预算控制"""

    def __init__(self, agent: "ChatService"):
        self.agent = agent
        self.budgets = DEFAULT_BUDGETS.copy()
        self.prefix_hash: Optional[str] = None
        self.workspace_fingerprint: Optional[str] = None

    async def build_prompt(self, request: ChatRequest) -> str:
        """组装完整 prompt，带预算控制"""
        sections = {}

        # 1. System Prefix（带缓存哈希）
        prefix = self._build_prefix(request.user_id)
        self.prefix_hash = hashlib.sha256(prefix.encode()).hexdigest()
        sections["prefix"] = prefix

        # 2. Engineer Memory（限 800 chars）
        sections["engineer_memory"] = render_engineer_memory(
            self.agent.engineer_memory,
            request.query,
            max_chars=self.budgets["engineer_memory"].max_chars,
        )

        # 3. Relevant Cache（如果缓存命中）
        cache_hit = self.agent.cache_matcher.find_match_sync(
            request.query, ...
        )
        if cache_hit:
            sections["relevant_cache"] = self._render_cache_hit(cache_hit)

        # 4. History（分层压缩）
        sections["history"] = await self._build_history_section(
            request.conversation_id,
            request.user_id,
        )

        # 5. Current Request（永不裁剪）
        sections["current_request"] = self._build_request_section(
            request.query, context_chunks
        )

        # 6. 预算控制（超预算时按优先级裁减）
        sections = self._apply_budget(sections)

        # 7. 组装最终 prompt
        return "\n\n".join(
            sections.get(name, "")
            for name in ["prefix", "engineer_memory", "relevant_cache",
                         "history", "current_request"]
            if sections.get(name, "").strip()
        )

    def _apply_budget(self, sections: Dict) -> Dict:
        """超预算时按优先级裁减"""
        total = sum(len(v) for v in sections.values())
        if total <= sum(b.max_chars for b in self.budgets.values()):
            return sections

        # 按 reduction_priority 升序裁减（优先级高的先裁）
        sorted_sections = sorted(
            self.budgets.items(),
            key=lambda x: x[1].reduction_priority,
        )
        for name, budget in sorted_sections:
            if name not in sections:
                continue
            if total <= sum(b.max_chars for b in self.budgets.values()):
                break
            if len(sections[name]) <= budget.floor_chars:
                continue
            # 裁到 floor
            sections[name] = sections[name][:budget.floor_chars]
            total = sum(len(v) for v in sections.values())

        return sections
```

```python
async def _build_history_section(
    self, conversation_id: str, user_id: UUID
) -> str:
    """构建分层压缩的历史记录"""
    messages = await conversation_service.get_messages(
        conversation_id, user_id
    )
    if not messages:
        return ""

    # 最近窗口（完整保留）
    recent_window = 6  # 轮
    recent = messages[-recent_window * 2:]  # user + assistant 对

    # 旧历史（压缩）
    old = messages[:-recent_window * 2]

    parts = []

    if old:
        # 压缩旧历史
        compressed = self._compress_history(old)
        if compressed:
            parts.append("-- 早期对话 --\n" + compressed)

    if recent:
        # 保留完整格式
        recent_text = "\n".join(
            f"{m.role}: {m.content[:900]}"
            for m in recent
        )
        parts.append("-- 近期对话 --\n" + recent_text)

    return "\n\n".join(parts)


def _compress_history(self, messages: List[Message]) -> str:
    """压缩旧历史：去重 + 摘要"""
    seen_queries = set()
    compressed = []

    for msg in messages:
        if msg.role == "user":
            # 去重：同样的提问只保留一次
            query_key = msg.content[:60].lower().strip()
            if query_key in seen_queries:
                continue
            seen_queries.add(query_key)
            compressed.append(f"User: {msg.content[:150]}")
        elif msg.role == "assistant":
            # 只保留第一句结论
            first_line = msg.content.split("\n")[0][:120]
            compressed.append(f"Assistant: {first_line}")

    return "\n".join(compressed[-20:])  # 最多 20 行
```
